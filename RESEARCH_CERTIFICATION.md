# Phase 16.4 — Research Certification (Evidence-first + Replay + Audit)

## Overview

This document specifies the **constitutional research certification framework** for Phase 16.

Phase 16 certification transforms autonomous research outputs into **knowledge-eligible** artifacts only after:

- replayable determinism is verified
- evidence is complete and referenced by immutable hashes
- independent evidence-only audit succeeds
- archaeological lineage reconstruction succeeds
- freeze certification manifests are produced

This document is **spec-only** (no implementation).

---

## Certification Principle

**No autonomous research output becomes accepted knowledge without a valid certificate.**  
No certificate is valid without replayable evidence referenced by immutable IDs.

Phase 16 maintains Phase 15’s evidence-first methodology and fail-closed certification gating.

---

## Certificate Types (Phase 16)

### 1) ResearchProgramCertificate
**Purpose**: Attests that an autonomous `ResearchProgram` completed the full constitutional lifecycle up to a specified acceptance boundary.

**Contents (schema-level fields)**
- certificate_id (content-addressed)
- schema_version: `16.x.y`
- subject_type: `RESEARCH_PROGRAM`
- research_program_id (content-addressed)
- primary_question_id (content-addressed)
- knowledge_gap_id (content-addressed)
- evidence_bundle_ids (content-addressed)
- validation_artifact_ids (content-addressed)
  - replay_certificate_hashes (content-addressed; produced by replay subsystem later)
  - audit_certificate_hash (content-addressed; produced by evidence-only auditor later)
- lineage_root_hash (content-addressed)
- issuer_id + issuer_signature (Ed25519 or equivalent)
- timestamp

**Issuance Criteria**
- The program is in the correct terminal lifecycle state (e.g., `FROZEN_ELIGIBLE` or equivalent).
- Statistical validation artifacts exist and match the program’s frozen statistical requirements.
- Replay prerequisites are satisfied at required replay level.
- Evidence-to-conclusion mapping is complete and reconstructable.
- Archaeology lineage root matches the recorded lineage proof.

---

### 2) DiscoveryCertificate (Continuity with Phase 15)
Phase 16 extends the Phase 15 discovery certificate logic to autonomous discoveries generated by the research pipeline.

**Rule**: Phase 16 must reuse Phase 15’s certificate semantics for discovery acceptance:
- evidence hashes required
- replay verified
- independent audit required for final certification gates

---

### 3) ResearchReplayCertificate (continuity with replay subsystem)
A certificate that attests deterministic replay and divergence checks for a research program.

The replay certificate is a prerequisite for research program acceptance.

---

### 4) ResearchAuditCertificate (evidence-only independent audit)
A certificate that attests an independent evidence-only audit has reproduced:

- the mapping from evidence bundles → validation results
- the mapping from validation results → theory update proposal
- the mapping from theory update proposal → knowledge integration decisions
- the resulting lineage reconstruction

**Evidence-only**: auditor cannot import runtime state; it consumes immutable artifacts only.

## Certification Gates (Fail-Closed)

Phase 16 defines gates that must pass in order. Any failure blocks knowledge acceptance.

### Gate 0 — Freeze Eligibility Check
- Research contracts and ontology are frozen for the epoch
- Program artifacts include required frozen schema ids

### Gate 1 — Evidence Completeness Check
- evidence bundles exist
- evidence bundles reference all required measurements
- evidence normalization proofs exist

### Gate 2 — Replay Determinism Check
- verifier recomputes deterministic outputs
- content-addressed IDs and Merkle root proofs match
- divergence report indicates no mismatch, or mismatch is explained and certified as non-critical (default: fail-closed)

### Gate 3 — Statistical Validation Check
- statistical validation outputs exist
- outputs satisfy frozen statistical requirements:
  - alpha / power / confidence targets
  - robustness/sensitivity diagnostics present

### Gate 4 — Archaeological Lineage Reconstruction Check
- reconstruction can explain every decision from:
  - knowledge gap → question → plan → experiment design → evidence bundle → validation → theory update proposal
- lineage root hash matches

### Gate 5 — Independent Evidence-only Audit
- evidence-only auditor emits `ResearchAuditCertificate`
- certificate issuer authorized
- certificate registered in audit registry (later implementation)

### Gate 6 — Freeze and Certification Manifest
- emit:
  - `RESEARCH_FREEZE.md`
- RESEARCH_CERTIFICATE.json (final package)
  - proof artifacts for archaeology and reconstruction

## Certificate Issuance Process (Protocol-managed)

Certification is modeled as a protocol-managed issuance process (issuer verifies; it does not make scientific judgments).

### Request → Verify → Sign → Register

1. **Request received**
   - includes subject artifact IDs (research program + dependencies)
2. **Verify prerequisites**
   - schema ids, evidence completeness, replay/cert requirements
3. **Verify certificate chain**
   - dependency certificates and lineage roots are valid
4. **Compute certificate content hash**
5. **Sign and register**
6. **Emit certificate issued event**
7. **Update lineage status**
   - subject becomes eligible for later knowledge integration

---

## Revocation / Invalidity (Spec Rule)

Certificates are invalidated if:

- evidence fraud is detected
- replay divergence occurs and invalidates claims
- protocol mismatch is found (e.g., missing replay level)
- audit certificate is revoked/failed
- lineage reconstruction fails

Revocation must preserve an immutable audit trail (append-only).

## Summary

Phase 16 certification guarantees:

- evidence-first knowledge acceptance
- replay-verified determinism
- evidence-only independent audit
- archaeologically explainable lineage
- freeze before integration into Phase 17 world modeling

This document defines the certification framework at the specification level.
