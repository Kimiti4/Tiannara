## Seven Engineering Rules

Seven immutable rules govern all implementation:

1. **Never introduce new subsystem** if existing constitutional component can perform responsibility
2. **Prefer composition over inheritance**
3. **Prefer events over direct calls**
4. **Prefer institutional behavior over module growth**
5. **Prefer validation over assumption**
6. **Prefer architectural simplicity over feature accumulation**
7. **No new persistent state** unless it extends existing constitutional state model ← NEW

### Rule 7 Detail: No New Persistent State

**Rule**: No implementation may introduce new persistent state unless it can be expressed as an extension of an existing constitutional state model.

In practice that means:
- If information belongs in the Knowledge Graph, **don't create another graph**
- If it belongs in Memory, **don't create another cache**
- If it belongs in Lifecycle, **don't invent another registry**
- If it belongs in Governance, **don't create another policy engine**
- If it belongs in the Ledger, **don't create another accounting table**

Over time, this rule prevents one of the most common forms of architectural drift in large systems: **duplicated state**.
