## Residual scope (not covered here) — recorded, not hidden

- **F-ARC-240 (new):** `TiannaraRuntime.MultiWorld.WorldSupervisor` is not started by any supervisor, so the last hop
  of the chain cannot deliver a termination. The switch now runs, accepts requests, reports them and recovers — but the
  **execution** of a kill is still not reachable. This is the same root cause as F-ARC-226 (the launcher gap) and is not
  fixed by this step.
- **D-ARC-015 (new, open):** the CIS arbitration falls back to `:approve` for an unrecognised (safety mode, severity)
  pair, and `:normal` mode with `:critical` severity is approved without secondary validation. Changing the default to
  deny is a constitutional decision and was deliberately not made inside a stabilization batch.
- The two retired kill-switch modules remain in the tree as unowned code. Retiring them is a file removal under the
  operator's plan (R2, with the ownership decision) and is not part of this step.

## Evidence gaps (recorded, not hidden)

- No application was booted for this evidence; the runtime test environment starts the application, which is how the
  switch is observed running — that is a test-environment observation, not a production deployment observation.
- The end-to-end kill (request → arbitration → termination) is **not** demonstrated, for the reason recorded above.
