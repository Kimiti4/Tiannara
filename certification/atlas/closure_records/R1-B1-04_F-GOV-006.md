## Behaviour preserved, behaviour changed (explicit)

| Behaviour | Before | After |
|---|---|---|
| Verdict for a decision that **violates** a principle | unchanged taxonomy | **unchanged** (baseline scoring keeps the exact pre-change score and verdict) |
| Verdict for a fully compliant, well-evidenced decision | `:conditional` (approval unreachable: compliance capped at 0.70) | **`:approved`** (compliance ≥ 0.80, confidence ≥ 0.70, no violated principle) |
| Verdict for a decision that violates a hard invariant | `:rejected` | `:rejected` (unchanged) |
| Compliance score of a compliant decision | 0.70 | ≥ 0.80 |
| Plugin registry started, no principles registered | would score 1.0 and approve everything | falls back to the built-in assessment (fail closed) |
| Plugin registry started with the two shipped principles | replaced the 11-principle built-in assessment (a decision with no evidence reported **no** violated principle) | **augments** the built-in assessment; the built-in coverage is preserved |
| Existing governance error taxonomy (`:conditional_conditions_unmet`, `:requires_human_approval`) | as before | unchanged (proved by the untouched governance suites) |

## Decisions recorded (not improvised)

- **D-ARC-011 — the built-in assessment is the authoritative evaluation path.** The plugin registry is *not* activated
  by this change, because activating it today would change the constitutional coverage of every decision; the guard
  makes a future activation safe, and the augment-vs-replace contract is now fixed to *augment*.
- **D-ARC-012 — open:** the two shipped plugin principles declare `weight 1.0` each while the eleven built-in weights
  sum to 1.0, so if the registry is ever activated the plugins would carry two thirds of the score. How the weights
  should be scaled is an explicit design question, not something to settle inside a stabilization batch.
- **D-ARC-013 — open:** routing a violating decision to `:requires_human` is tempting, but until the human-approval
  resume path exists (F-GOV-004) such a decision would be parked with no way to resume. The taxonomy is therefore left
  alone; the decision is revisited when the resume path lands.

**Residual scope (not covered here):** F-GOV-004/F-GOV-017 (the human-approval resume path) and F-GOV-010
(certificate binding) remain **OPEN**.

## Evidence gaps (recorded, not hidden)

- No application was booted; the proof is structural and test-bound, not runtime-bound.
- The confidence formula reads a *different* evidence signal than the evidence principle: `compute_confidence/3` uses
  `payload[:evidence_count]` while the `evidence_based` principle uses `payload[:evidence]`. A caller must therefore
  carry both for an approval to be reachable. Recorded as **F-GOV-025**; not fixed here, because changing the
  confidence formula would alter every decision's score.
- The plugin path's failure handling is still a silent `rescue` that falls back to the built-in assessment; a broken
  plugin would be masked rather than reported. Recorded as part of F-GOV-025's scope for the next design pass.
