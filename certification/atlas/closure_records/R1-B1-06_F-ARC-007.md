## Behaviour preserved, behaviour changed (explicit)

| Behaviour | Before | After |
|---|---|---|
| `HashVerifier` on a true / false / missing-expectation claim | pass / fail / fail | **unchanged** (it was already fail-closed) |
| `HashVerifier` on a missing input | **raised** | reported as a failure |
| `GraphVerifier` on any claim | **always pass, `failures: 0`** | pass only when the computed hash equals the expectation; missing expectation → failure |
| `ProofVerifier` on a missing expectation | **pass** ("independent fingerprint") | failure with a reason |
| `ProofVerifier` on a missing proof summary | fail | unchanged |
| `RuntimeVerifier` on a missing expression | **raised** | reported as a failure |
| `RuntimeVerifier` on a true / false / missing-expectation claim | pass / fail / fail | unchanged |
| The tracked "220 / 220 PASS" report | presented as a result | **retired as non-evidence**, preserved as history with a supersession marker |

## Residual scope (not covered here)

- No fresh audit report has been produced yet. A new report requires an artifact that carries verifiable
  expectations; the artifacts that produced the 220/220 run do not, so under the new fail-closed contract they would
  report failures. That is the honest outcome and is **not** a regression to be hidden.
- The audit tool still verifies only hashes, proof fingerprints, graph roots and runtime fingerprints; it is not a
  constitutional audit of the platform (F-GOV-001 remains open, and the CAE/CAP specifications are still not in the
  repository).
- The audit project is now in CI, but the wider CI scope (the Python, Docker and release workflows that still only
  run on `main`/`master`) remains open as F-PLT-004 / Batch 6.4.

## Evidence gaps (recorded, not hidden)

- The verifier suite is new and small; it proves the fail-closed contract, not the correctness of the audit
  methodology itself. The methodology's own assumptions (the canonicalisation and fingerprint algorithms) are
  replicated from the runtime, not independently derived — that limitation predates this change and is not addressed
  by it.
- No application was booted and no runtime artifact was verified in this step.
