# Tiannara Phase 12 Capability Board

**Status**: ACTIVE  
**Date**: June 13, 2026  
**Phase**: 12 - Institutional Cognition  
**Engineering Discipline**: Constitutional Execution Program

---

## Purpose

This board tracks **institutional capabilities** rather than subsystems or phases. Every row represents a measurable institutional behavior that must:

1. Compose existing constitutional components
2. Preserve all 11 constitutional invariants
3. Provide complete explanatory traceability
4. Demonstrate correctness through validation scenarios

**No new subsystems are created.** Only institutional capabilities are realized through composition of frozen infrastructure.

---

## Board Structure

| Column | Purpose |
|--------|---------|
| **Capability** | What institutional behavior is being added? |
| **Constitutional Components Used** | Which frozen components compose this capability? |
| **Validation Scenario** | How do we prove it works correctly? |
| **Invariant Coverage** | Which constitutional invariants does it preserve? |
| **Scientific Competency** | What kind of scientific institution is this building? |
| **Maturity** | Prototype → Validated → Stable → Frozen |

## Usage Guidelines

### Adding New Capabilities

When a new capability is proposed:

1. **Define the institutional behavior** (not the subsystem)
2. **Identify constitutional components** it composes (must reuse existing)
3. **Design validation scenario** proving correctness
4. **Map invariant coverage** (which invariants does it preserve?)
5. **Ensure explanatory traceability** (Principle 11)

If any step fails, redesign the capability—not the Constitution.

### Updating Maturity

- Move from ⚪ → 🟡 when implementation begins
- Move from 🟡 → 🟢 when validation scenario passes
- Move from 🟢 → 🔵 after sustained operation without issues
- Move from 🔵 → ⚫ when capability is mature and stable

### Blocking Dependencies

Capabilities list their blocking dependencies. A capability cannot begin until all blockers reach at least 🟢 Validated status.

**Primary dependency chain**:
- 12.1 (Unified Research Runtime) blocks everything
- 12.2 (Discovery Exchange) blocks 12.9 (Research OS Beta)
- 12.9 blocks 12.10 (Distributed Validation)
- 12.11 (Epistemic Coarse Graining) blocks 12.13 (Active Epistemic Foraging)

## Constitutional Compliance Check

Before marking any capability as 🟢 Validated, verify:

- [ ] Does it conform to all 11 Core Principles?
- [ ] Does it preserve all applicable Constitutional Invariants?
- [ ] Does it reuse existing components (no new subsystems)?
- [ ] Does it ask "What capability?" not "What subsystem?"
- [ ] Does it expose hooks for CIS/telemetry/lifecycle/events/governance?
- [ ] Does it register in Runtime Atlas (if new entity type)?
- [ ] Can every decision be traced (Principle 11)?
- [ ] Does governance validate before mutation (Principle 6)?
- [ ] Does it emit semantic events (Principle 2)?
- [ ] Does it track lifecycle (Principle 3)?

**If any check fails, capability is unconstitutional. Redesign required.**
