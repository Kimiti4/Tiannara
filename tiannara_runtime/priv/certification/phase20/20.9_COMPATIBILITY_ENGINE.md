# Compatibility Engine (Phase 20.9)

## Purpose

The Compatibility Engine validates the compatibility of proposed changes against the existing constitutional generation. It checks all seven constitutional domains to ensure no regression, contradiction, or violation.

## Seven Domain Compatibility Checks

1. **State Compatibility**
   - New state structures compatible with existing state schema
   - No data loss on migration
   - State transition functions remain valid

2. **Knowledge Compatibility**
   - Knowledge axioms preserved
   - No contradictory knowledge assertions
   - Inference chains remain valid

3. **Mathematical Compatibility**
   - Mathematical foundation preserved
   - Theorem consistency maintained
   - Computational models unchanged

4. **World Model Compatibility**
   - World model assumptions preserved
   - Environmental constraints respected
   - Simulation fidelity maintained

5. **Planning Compatibility**
   - Planning algorithms remain valid
   - Goal structures compatible
   - Constraint satisfaction preserved

6. **Runtime Compatibility**
   - Runtime behaviour preserved
   - No breaking API changes
   - Performance characteristics maintained

7. **Archaeology Compatibility**
   - Archaeology schema preserved
   - Replay chains maintain continuity
   - Cold storage format unchanged

## Compatibility Levels

1. **Fully Compatible** — No changes required; direct promotion possible
2. **Conditionally Compatible** — Minor adaptations needed; conditions recorded
3. **Compatible with Migration** — Requires migration plan; rollback required
4. **Incompatible** — Proposal rejected; detailed incompatibility report generated

## Output

CompatibilityReport containing:
- Per-domain compatibility verdicts
- Migration requirements (if any)
- Compatibility root hash (for certification)
- Evidence chain references
- Conditions for promotion
