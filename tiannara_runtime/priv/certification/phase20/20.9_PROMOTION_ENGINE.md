# Promotion Engine (Phase 20.9)

## Purpose

The Promotion Engine manages the staged pipeline through which approved improvements are promoted from development through to production. It ensures each promotion stage is properly validated, certified, and replayable.

## Promotion Pipeline Stages

```
Candidate
    → Validated
        → IntegrationReady
            → Sandbox
                → Canary
                    → ProductionCandidate
                        → Current
                            → Historical
```

1. **Candidate** — Initial state after decision approval
2. **Validated** — Passed compatibility checks
3. **IntegrationReady** — All dependencies resolved, migration planned
4. **Sandbox** — Deployed in isolated sandbox environment
5. **Canary** — Limited exposure with monitoring
6. **ProductionCandidate** — Ready for full production promotion
7. **Current** — Active generation state
8. **Historical** — Archived after superseded

## Promotion Rules

- Each stage requires its own certification
- Stage transitions are deterministic and replayable
- Rollback must be possible from any stage
- Time-limited certifications require renewal
- Evidence chains propagate through stages

## Output

PromotionDecision records containing:
- Decision ID (content-addressed)
- Target promotion state
- Decision type (Approve/Reject/Defer/Conditional)
- Evidence summary
- Conditions (if any)
- Risk assessment
- Rationale
- Deciding authority
- Fingerprint
