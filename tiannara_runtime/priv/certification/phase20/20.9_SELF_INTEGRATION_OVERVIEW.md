# Self-Integration Architecture (Phase 20.9)

## Overview

Phase 20.9 defines the Self-Integration layer of the Constitutional Operating System. It orchestrates the promotion of improvements generated by Phase 20.6 (Engineering), Phase 20.7 (Experimentation), and Phase 20.8 (Optimization) into the existing constitutional generation.

## Architecture

```
  Improvement Proposals (20.6/20.7/20.8)
                  |

```

## Six Engines

1. **Decision Engine** — Evaluates proposals, computes risk assessments, makes deterministic integration decisions
2. **Compatibility Engine** — Validates compatibility of proposed changes against existing constitution
3. **Promotion Engine** — Manages staged promotion (sandbox → canary → production candidate → current)
4. **Runtime Evolution Engine** — Handles generation transition, migration coordination across 7 domains
5. **Generation Promotion** — Cross-generation promotion lifecycle management
6. **Rollforward Engine** — Executes forward migration with full verification and rollback capability

## Key Properties

- All decisions are deterministic and evidence-based
- Every step is replayable via content-addressed hash chains
- All artifacts preserved for archaeology
- Rollback plans required for every transition
- No direct runtime modification — only certified generation promotion
- Independent audit required for certification
