# Self-Integration Replay (Phase 20.9)

## Purpose

The Self-Integration Replay subsystem provides deterministic replay verification for the entire integration process. It enables independent verification of integration decisions, compatibility checks, promotions, transitions, and rollforwards.

## Replay Types

1. **Proposal Replay** — Replay decision computation from proposal and state
2. **Compatibility Replay** — Replay compatibility verification
3. **Verification Replay** — Replay verification of any integration stage
4. **Promotion Replay** — Replay promotion decision
5. **Rollforward Replay** — Replay rollforward transformation
6. **Freeze Replay** — Replay generation freeze verification
7. **Full Replay** — Replay complete integration process

## Replay Chain

Each replay consists of an ordered sequence of steps:
```
Step 1: [stage, input_hash, output_hash, step_hash]
Step 2: [stage, input_hash, output_hash, step_hash]
...
Root: final chain root hash
```

Each step_hash = SHA-256(stage || input_hash || output_hash || previous_step_hash)

## Verification

For each replay:
1. Verify step ordering is acyclic
2. Verify each step hash matches its inputs and outputs
3. Verify chain root hash matches computed root
4. Verify all hashes_match flag
5. Verify cold storage independence (replay from archaeology)

## Output

SelfIntegrationReplay records containing:
- Replay ID (content-addressed)
- Integration session reference
- Replay type
- Ordered step hashes
- Root hash
- All hashes match flag
- Status (Pending/Verified/Failed)
- Fingerprint
