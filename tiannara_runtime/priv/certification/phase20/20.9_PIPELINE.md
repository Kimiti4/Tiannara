# Self-Integration Pipeline (Phase 20.9)

## Purpose

The Self-Integration Pipeline orchestrates the complete integration flow — from proposal receipt through decision, compatibility, promotion, generation transition, and rollforward — into a single cohesive process. It ties together all six engines of Phase 20.9.

## Pipeline Stages

```
Stage 1: Proposal Ingestion
  Input: Improvement proposal from 20.6/20.7/20.8
  Output: Parsed IntegrationProposal
  Engine: (interface layer)

Stage 2: Decision
  Input: IntegrationProposal
  Output: Decision outcome (approve/reject/defer/conditional)
  Engine: Decision Engine

Stage 3: Compatibility Verification
  Input: Approved proposal + current constitutional state
  Output: Compatibility report
  Engine: Compatibility Engine

Stage 4: Promotion Management
  Input: Compatibility report + proposal
  Output: PromotionDecision with target stage
  Engine: Promotion Engine

Stage 5: Generation Transition
  Input: PromotionDecision
  Output: GenerationTransition record
  Engine: Runtime Evolution Engine

Stage 6: Rollforward Execution
  Input: GenerationTransition
  Output: RollforwardRecord
  Engine: Rollforward Engine

Stage 7: Certification
  Input: All prior stage outputs
  Output: SelfIntegrationCertificate
  Engine: (certification layer)

Stage 8: Replay Verification
  Input: Certificate + all records
  Output: Replay chain verification
  Engine: (replay layer)

Stage 9: Archaeology Deposit
  Input: All artifacts
  Output: Archaeology deposit records
  Engine: (archaeology layer)
```

## Pipeline Properties

- Each stage is independently replayable
- Stages are sequential (no parallelism in integration flow)
- Each stage produces a content-addressed record
- Pipeline can be paused between stages
- Rollback possible from any stage
- Full audit trail maintained
