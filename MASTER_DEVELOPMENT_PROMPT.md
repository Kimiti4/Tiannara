## Engineering Requirements

For **every implementation**:

1. **Explain where it belongs in the architecture**
   - Which epoch? Which phase? Which subsystem?

2. **Explain why it does not duplicate existing systems**
   - What existing functionality serves this purpose?
   - Why is a new subsystem necessary?

3. **Show subsystem dependencies**
   - What canonical APIs does it consume?
   - What invariants does it maintain?

4. **Define invariants**
   - What must always be true?
   - How is it verified?

5. **Define validation campaigns**
   - What simulations prove correctness?
   - What metrics demonstrate success?

6. **Define telemetry**
   - What is observed?
   - What is measured?
   - What alerts trigger?

7. **Define failure modes**
   - What can go wrong?
   - How is it detected?
   - How is it recovered?

8. **Define recovery mechanisms**
   - Automatic recovery procedures
   - Manual intervention protocols
   - Rollback strategies

9. **Update Runtime Atlas**
   - Document architectural changes
   - Update dependency graphs
   - Revise component boundaries

10. **Update Validation Matrix**
    - Add new test cases
    - Update invariant checks
    - Expand regression suite

### Completion Criteria

No implementation is considered complete until:

- ✅ Integrated (connected to canonical APIs)
- ✅ Instrumented (telemetry active)
- ✅ Benchmarked (performance measured)
- ✅ Validated (invariants hold)
